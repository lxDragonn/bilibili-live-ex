# Bilibili 直播增强

为 Tampermonkey 编写的独立脚本，参考 [douyuEx](https://github.com/qianjiachun/douyuEx) 的自动最高画质和观众/消费统计功能设计。

当前公开版本：**1.0.0**。包含开发阶段全部画质修复及安全加固。[安全审查与限制](SECURITY.md) · [更新记录](CHANGELOG.md)

## 安装

1. 浏览器安装并启用 Tampermonkey。
2. 在 Tampermonkey 管理面板选择“添加新脚本”，删除默认内容，将 **bilibili-live-ex.user.js 的全部内容**粘贴进去并保存。
3. 打开或刷新 `https://live.bilibili.com/数字房间号`，左下角会出现“直播增强”面板。也支持 `/blanc/数字房间号`。
4. 保持“自动最高可用画质”勾选。面板标题可以拖动，面板可以收起。

脚本可直接安装，无需构建、Node.js、API 密钥或额外统计服务。首次安装会由 Tampermonkey 下载固定版本的 pako 和 Google Brotli 解码器；需要能够访问元数据中列出的 jsDelivr 地址。开发测试依赖不参与浏览器运行。

运行时依赖已添加 SHA-256 校验，下载内容不匹配时 Tampermonkey 将拒绝加载。在 Edge 中需要启用扩展所要求的开发人员模式/用户脚本权限，然后刷新直播间。

## 功能

### 自动最高可用画质

- 从页面 `livePlayer.getPlayerInfo().qualityCandidates` 中选择最高 QN，优先通过 `switchQualityAsync` 切换，旧播放器使用 `switchQuality`。传入字符串 QN 和候选项的 HDR 类型，并读回二者确认。
- 读取当前画质确认切换结果；支持播放器晚加载、重新创建和网页内切房。
- 开启时持续检查，页面自动降画质或手动降低画质后会恢复最高档。希望保留手动选择时关闭开关；开关状态保存在当前站点的本地存储。
- 跳过标记为禁用或锁定的档位。每次请求最多等待 20 秒读回确认，确认超时或请求报错才计为失败；连续失败三次再尝试较低档，一分钟后重新探测。请求之间至少间隔八秒。
- 视频开始播放、媒体信息就绪时立即检测；切回标签页、页面恢复或网络恢复时重新探测。候选画质列表更新也会清除旧的失败记录。
- “重试画质”按钮可清除失败记录并重新检测，不清空统计；正在进行的切换仍会等待确认，避免重复请求。
- 不解锁平台权限。登录、账号资格、主播源画质、网络或平台播放器变更都可能影响结果。切换过程中显示“待确认”，不会把调用成功当作实际成功。

### 人数与付费统计

| 指标 | 口径 |
| --- | --- |
| 在线人数 | `ONLINE_RANK_COUNT.online_count`，优先保留平台的显示文本；可能存在上限，缺失时显示“未提供” |
| 看过人数 | `WATCHED_CHANGE.num`，平台累计看过人数，不是实时在线人数 |
| 高能用户 | `ONLINE_RANK_COUNT.count`，与在线人数及观察到的付费人数分别显示 |
| 付费人数 | 本次观察中，付费事件发送者按可识别 UID 去重；匿名消息不虚构 UID |
| 付费总额 | 金瓜子礼物、醒目留言（SC）、上舰广播金额的合计估算 |
| 付费事件数 | 已计入的消息事件数量；不是支付订单数或礼物件数 |
| 人气值 | 弹幕心跳包的值，仅作辅助信息，明确不视为人数 |

**观察范围从脚本本次加载开始。刷新页面、切换房间或手动重置会清空统计。** 同页下播后保留累计值，再开播继续累计本次观察；需要单场统计时自行重置。平台累计看过人数与本地付费观察期不一定相同。

金额规则：

- `SEND_GIFT` 只计 `coin_type === "gold"`，优先使用 `total_coin / 1000` 元。仅当总价缺失时才使用 `price × num / 1000`；零价值不回退到标价。
- `SUPER_CHAT_MESSAGE.price` 单位为元。
- `GUARD_BUY.price × num / 1000` 按上舰标价估算，不保证反映折扣、首购、续费等实际扣款。
- 内部使用整数金瓜子单位，避免小额累计的浮点误差；最多显示三位小数。
- 不重复累计 `COMBO_SEND`、`USER_TOAST_MSG`、`SUPER_CHAT_MESSAGE_JPN` 等展示/汇总消息。
- 有交易标识时去重最近 50,000 笔；无标识的完全相同消息在五秒内去重。异常重复、无标识且内容完全相同的独立事件仍可能产生偏差。
- 缺失金额字段的事件跳过并提示；缺失 UID 的事件计入金额但不计去重人数。平台若隐藏或更换用户标识，去重人数也可能偏低或不准确。

**这不是全场账单，也不是主播收入或观众实际扣款。** 金瓜子礼物可能来自背包、活动或优惠。退款、撤回、SC 删除不会追溯冲减本次观察总额。未进入直播间之前、页面关闭、休眠或断线期间的数据不会补齐；服务端未广播的消费也无法统计。不能用高能榜人数代替全场付费人数。

## 使用与排错

- **导出统计**：下载当前汇总 JSON，包含房间号、观察时间、各项人数/金额和错误数，不导出付款者 UID。
- **人数旁的 `*`**：该指标超过 90 秒未更新；不能再认为是当前值。
- **一直等待消息**：先确认 Tampermonkey 已在该页运行，然后刷新直播间。脚本需要在页面创建弹幕 WebSocket 前加载，无法接管加载之前已存在的连接。
- **消息中断**：脚本等待页面自身重连；不另开连接、不替换页面的鉴权流程。重连恢复后继续累计，但断线期间缺失的数据不可恢复。
- **压缩包解析失败**：检查 Tampermonkey 是否成功下载两个 `@require` 资源；也可能是平台协议变化。错误包不会阻断后续消息解析。
- **一直等待播放器**：可能是尚未开播、播放被拦截，或 Bilibili 更换了播放器接口。本版本适配网页 `window.livePlayer`；不声称覆盖任意未来播放器。
- 本脚本监听主页面已有的 `/sub` 弹幕连接。如果平台改用 Worker 内的 WebSocket、其他传输方式，或其他扩展提前拦截了连接，本版本可能无法观测，面板会保持等待状态。
- 平台改动、网络丢包和消息限流都可能造成统计缺失。真实付费金额的完整性仍需与实际事件核对。

## 实现与验证

单个 `.user.js` 文件包含协议解码、统计、画质控制和面板；使用 Shadow DOM 隔离面板样式。只监听页面现有连接，不上传统计数据、不请求第三方直播统计接口、不修改页面收到的弹幕内容。

开发验证（Node.js 20+）：

```sh
npm ci
npm run check
npm test
```

测试覆盖 zlib/Brotli 压缩、多包/扩展头/心跳、付费单位与去重、匿名用户、在线人数口径、画质失败重试、第三次切换成功，以及模拟浏览器内的面板更新、房间隔离、异步旧消息丢弃、连接中断和手动重置。模拟测试不能替代真实 Bilibili 页面验证。

### 画质修复与实测（2026-09-29）

- 修正传给播放器的 QN 类型：当前播放器要求字符串，数字参数会被解析为无效的 `0` 档。核对了实际页面加载的 [Bilibili 播放器源码](https://s1.hdslb.com/bfs/static/bilibili-live-player/room-player.01626800.prod.min.js)。
- 同时传入 HDR 类型，优先使用有返回结果的异步接口。改进慢速换流确认、失败冷却、迟到请求隔离及页面恢复触发，新增“重试画质”。
- 发布版 35 项离线回归测试通过，包含严格字符串参数、HDR 匹配、纯文本渲染、消息队列/解压限制及依赖校验测试。
- 开发阶段在 Edge + Tampermonkey 5.4.1、房间 `22209173` 实测：加载后自动从“自动（720P）”切至“1080P 原画（高帧率）”；手动选择 720P 后自动恢复 1080P；刷新后仍显示最高画质。播放器菜单与脚本面板交叉确认。
- 该实测仅覆盖上述房间当时提供的画质，不代表所有房间、HDR 设备和权限组合均已测试。已观察到在线、看过及高能用户消息更新，未用真实支付测试消费统计。
